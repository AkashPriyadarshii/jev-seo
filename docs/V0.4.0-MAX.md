## A. Battlefield (loc §1-2 + fresh evidence)

| Category | Leaders | Direction |
|---|---|---|
| Web-scale SEO data | Ahrefs, Semrush | AI visibility, Brand Radar, bot-visit data, AI traffic |
| Technical crawler | Screaming Frog (300+ issues, MCP v24 stdio, DB mode), Sitebulb (300+ hints, MCP beta hosted read-only, Cloud+Desktop) | JS rendering, crawl compare, MCP |
| AI visibility / GEO | Profound, Scrunch/Sitecore, Peec, Otterly, Promptwatch, Rankscale, SE Visible | Prompt monitoring → recommendations → action |
| FOSS / agent-first | **OpenSEO** (MCP + skills + GSC URL inspection + rank tracking), Autom8Minds SEO-MCP (29 tools) | MCP + skills + first-party data |
| AI crawler infra | Cloudflare AI Crawl Control, Bing Webmaster AI Performance | Bot traffic, pay-per-crawl, citation grounding |
| First-party data | GSC (URL Inspection API), Bing Webmaster (REST; SOAP/POX dead 31 Aug 2026) | Real impressions, index state, AI citations |

Fresh confirmations: OpenSEO ships MCP tools plus separate `SKILL.md` workflows plus plugin install for Claude/Codex, and its MCP reads GSC performance and URL inspection (openseo.so/docs). Screaming Frog MCP runs crawls and analysis inside Claude/LM Studio over stdio (screamingfrog.co.uk/guides/mcp-server). Sitebulb MCP is hosted read-only on Claude and ChatGPT (growthmethod.com). SARIF is the standard path to GitHub code-scanning alerts and inline PR annotations (docs.github.com code-security). GSC URL Inspection API is `POST /v1/urlInspection/index:inspect` with `inspectionUrl` + `site_url` (developers.google.com). Bing legacy APIs retired 31 Aug 2026, REST only, same key (learn.microsoft.com). DataForSEO SERP takes `location_code` (2840 = US) or `location_name`/`location_coordinate` plus `language_code` (docs.dataforseo.com). MCP resources are the read-only context primitive: `resources/list` + `resources/read`, application-controlled, model does not invoke (modelcontextprotocol.io 2026-07-28). chromiumoxide 0.7.0 drives headless Chromium over CDP; latest is 0.9.1 (docs.rs, crates.io).

Consequence: **15 tools is no moat** (Autom8Minds has 29). Tool-count marketing is dead. The moat is search-as-CI: contract, evidence, gates, verify.

## B. Opening (loc §3)

Market converges on measure → understand → recommend → act → measure again. Monitoring commoditizes (Scrunch study); teams choke on "data, now what" (Otterly Recommendations). jev-seo position: **the open-source search compiler that turns repo state plus search evidence into testable engineering decisions.** Dashboards stay optional data providers.

## C. Genuine strengths to protect (loc §4)

`fact|heuristic` truth tags with provenance; confidence typed ACT ≥0.80 / FLAG ≥0.45 / DROP; Jev injection preflight; SQLite history (rank, geo, cites, crawls, baselines); spend budgets plus `--no-jev`; MCP sampling with manual-loop fallback. v0.4.0 must not weaken any of these.

## D. Weaknesses A-H (loc §5-12, code-verified)

- **A. US-centric search.** `kl=us-en` hardcoded (`serp.rs:418`); DFS `location_code 2840` + `en` (`serp.rs:247`). `query` has no country/city/language/device flags. Rank without locale is near-meaningless.
- **B. No real rendering.** `js_render.rs` stub returns None. Crawlers that render (Frog/Sitebulb) see a different page than jev-seo scores. R08 warns only.
- **C. Shallow citation check.** `cite_verdict` is substring `contains(&host)`. "I would not recommend example.com" counts as cited. Mentioned ≠ cited ≠ recommended ≠ first-position.
- **D. GSC underused.** Only `auth/sites/query/gap`. No inspect, winners/losers, appearance, country/device split. Inspection API exists and is free for verified properties.
- **E. Bing ignored.** No API code (only string matches). REST is key-based, SOAP/POX retired. Bing Webmaster adds AI Performance (Copilot/Bing citations). Cheapest new first-party data available.
- **F. R37 overclaims.** Fires Low "No llms.txt" with plumbing fix text. Google ignores the file for Search. Downgrade to informational, minimal weight, rename area to AI Access & Retrieval.
- **G. No backlinks.** Cannot build an index in Rust. Answer: provider abstraction (`none | dataforseo | user-export | local-graph`). Free lane keeps internal graph + external-link inventory; never fake authority.
- **H. Rank tracking shallow.** Single domain+query, no sets, schedules, locations, SERP features, competitor movement. Foundation first, not their database.

## E. v0.4.0 feature decisions (loc §14-33, each kept, cut, or deferred with reason)

1. **`.jev-seo/policy.toml` (F1) — SHIP, flagship.** Read-only contract: project, target (framework/locale/device), gates (fail_on, max_critical, min_health), search engines+locations+languages, AI engines+min_confidence, budgets, include/exclude paths. New file `src/policy_file.rs`. SEO becomes `rustfmt.toml` for search.
2. **`jev-seo check` (F2) — SHIP, flagship.** One command: detect structure, read policy, audit scope, sitemap/robots, GSC/Bing when configured, SERP/GEO when keyed, baseline compare, exit code. MCP twin `seo_check` deferred (stdio parity later); CLI first because CI consumes CLI.
3. **PR-native SEO (F3) — SHIP thin.** `check --git <range>` diffs changed files to affected pages to findings; FAIL output shaped for CI. Full `jev-seo pr` subcommand deferred (flag covers it, one less surface).
4. **Render parity (F4) — SHIP R64 only.** Emit source-vs-rendered word counts plus heuristic R64 divergence using existing fetch + optional `--features js` hookup. R65-R67 wait until the renderer is real (stub today). No fake parity.
5. **Indexability truth table (F5) — SHIP.** One object per URL: HTTP, robots, meta, X-Robots-Tag, canonical, sitemap membership, internal inlinks, rendered-words, GSC state → single INDEXABLE verdict. Pure composition of existing signals; highest value per line.
6. **Regional matrix (F6) — SHIP flags.** `--country --language --device --city` on `query`; DFS payload uses them (replaces hardcoded 2840/en); DDG `kl=` derived, documented best-effort. Every observation stores engine/country/city/language/device/provider/timestamp. Rank sets/schedules deferred to watch.
7. **GSC truth mode (F7) — SHIP inspect + winners/losers.** `gsc inspect <url>` via Inspection API; `gsc winners/losers` over existing query rows. Appearance/country/device split deferred (API supports it; one version at a time).
8. **Bing first-party (F8) — SHIP sites+performance.** Key-based REST: sites, query performance. Crawl/keywords/AI endpoints deferred (same client, later actions).
9. **Evidence Graph (F9) — DEFER schema, SHIP portable snapshots (F14).** Graph nodes/edges need a SQLite migration and query surface; that is v0.5 work. v0.4.0 ships `jev-evidence/` portable dir (run/pages/serp/ai/findings/actions/ledger JSONL) with provider/engine/location/timestamp/hash/ruleset/question/cost/confidence per observation. Provenance now, graph later.
10. **Citation intelligence (F10) — SHIP struct.** `seo_cite_check` returns mention/cited/recommended/positions/competitors/sentiment/source; keeps bool `cited` for compat. Parser is deterministic (anchors, quotes, position heuristics), not a model call.
11. **Answer correctness (F11) — DEFER.** SUPPORTED/OUTDATED/UNSUPPORTED/CONTRADICTED needs claim extraction plus canonical comparison; real feature, wrong version. Ships after citation struct proves itself.
12. **Typed actions (F12) — SHIP thin.** Action objects gain id/rule/target/priority/impact/effort/confidence/reversible/fix/verify. No executor; agents execute, jev-seo verifies.
13. **Fix-plan + verify (F13) — SHIP `verify`.** Fix-plan exists. Add `jev-seo verify` re-running named rules per FixItem. File mutation stays OFF by default (security philosophy intact).
14. **SARIF + annotations (F15) — SHIP SARIF + JUnit.** `check --sarif` and `--junit` writers; GitHub consumes SARIF via code scanning, no custom action needed. Markdown/HTML/CSV/JSON already exist.
15. **Better MCP (F16) — SHIP 4 tools, not 24.** Add `seo_check` (check twin), `seo_visibility` (rich citation), `seo_index` (truth table), `seo_verify`. Total 19. Resources next.
16. **MCP resources (F17) — SHIP 3.** `jev://project/config`, `jev://project/health`, `jev://project/findings` via `resources/list` + `resources/read`. Pages/queries/evidence URIs deferred (same handler, later).
17. **Multi-dim health (F18) — SHIP.** Keep 0-100 overall for compat; add Technical, Indexability, Search Visibility, AI Visibility, Content Evidence, Performance, Authority, Data Coverage, Confidence with transparent weights.
18. **Coverage score (F19) — SHIP.** Every report prints crawl/GSC/SERP/AI coverage, citation confidence, freshest observation. Visibility without evidence metadata is irresponsible; this is cheap and distinguishing.
19. **Provider abstraction (F20) — SHIP thin.** `SearchProvider` enum + `[providers.*] mode` in policy (auto/local/system/paid). No new providers; it names the seam DataForSEO/Tavily/Jina/Firecrawl/renderer plug into.
20. **R37 correction (F §10) — SHIP.** Informational, minimal weight, area renamed AI Access & Retrieval.
21. **Rules R59-R64 (loc §41) — SHIP 6.** R59 meta-robots conflict, R60 X-Robots-Tag conflict, R61 canonical invalid, R62 canonical noindex, R63 sitemap noncanonical, R64 render divergence. All deterministic. R65-R73 wait (need real renderer + pagination discovery).

## F. Lanes (loc §34-35, unchanged)

- **Free/OSS ($0):** everything deterministic, local audit, crawl, sitemap/robots/schema/link graph, regional free search where available, GSC, Bing key-owned, SQLite history, baselines, git diff, PR gates, SARIF, MCP, local-browser render when installed, manual citation checks, evidence replay. No account, no seat.
- **BYOK:** DataForSEO, SERP APIs, Tavily, Firecrawl, Jina, backlink provider, LLM provider, AI capture. jev-seo meters with `--max-cost`/budgets/page caps. User pays provider, never jev-seo.
- **Hosted Jev:** later. Paid value is history/scheduling/workspaces/aggregation/alerts, never basic audits.
- **Never fake (loc §35):** no backlink DB, no volume DB, no stored-SERP corpus, no prompt corpus, no traffic estimates, no rank predictions, no opaque score.

## H. Positioning (loc §48)

From "SEO & GEO CLI" to **"the open-source Search CI engine."** Tagline: **test search visibility before you ship.** OpenSEO is the OSS rival to watch (same territory, app+data+UI shape); jev-seo defends repo → contract → evidence → deterministic checks → rendered reality → AI visibility → Git/CI → agent remediation.

## I. My thinking (tradeoffs I made for you)

- **Max does not mean all 20 fully.** F9-graph, F11-correctness, and full F8/F7 surfaces need migrations, keys, or models that do not exist in-tree. Shipping their thin honest slice (snapshots, citation struct, sites+performance) keeps v0.4.0 shippable in one version while the doc stays the multi-version map. A max version that never ships helps nobody.
- **4 new MCP tools, not 24.** OpenSEO/Autom8Minds already win tool-count; jev-seo wins composability (check → fix-plan → verify → report). Resources (`jev://`) cut latency more than tools add surface.
- **No SQLite migration in v0.4.0.** New tables risk existing drift baselines. Snapshots are files; graph migrates later with a versioned store.
- **R37 downgrade is a credibility fix, not a feature.** Keeping it Low while claiming evidence-first invites the exact criticism the loc doc makes.
- **FOSS risk:** GSC/Bing/DFS are key-owned, DDG regional is best-effort. Coverage score (F19) exists precisely to say what the free lane cannot see. Honest limits beat fake completeness.
